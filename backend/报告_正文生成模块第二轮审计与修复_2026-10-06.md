## 四、修复项清单

### BUG-1：未闭合普通代码围栏内容泄漏为正文段落（P1）

**现象**：AI 输出的 `python / `json / `text 等普通代码块如果未闭合（缺结尾 `），块内代码原文（import/def/return/JSON 载荷等）全部残留为正文段落，出现在标书文档中形成乱码。

**根因**：



* `_protect_chart_fences` 只处理 mermaid/chart-json 图表围栏

* 后续全局正则 `re.sub(r"```[\w]*\n?", "", raw)` 只删围栏起始行，不删块内代码行

* 未闭合块的所有内容行全部泄漏为正文

**实测验证**：



````
输入：```python\nimport os\ndef setup():\n    return True\n（无闭合）
修复前：import os / def setup() / return True 全部变成正文 paragraph block
修复后：整个坏块被干净删除，正文干净
````

**修复方案**：



* 文件：`app/services/content_cleaning.py`

* 新增函数：`_strip_unclosed_plain_fences(text: str) -> str`（约 25 行）

* 接入位置：`clean_generated_content` 中 `_protect_chart_fences` 之后、全局围栏正则之前

* 逻辑：行级状态机逐块判定闭合性 —— 闭合块保留（后续正则剥围栏行），未闭合坏块从起始行到文末全部删除

**向后兼容性**：



* 闭合普通代码块：内容保留为正文（既有行为不变）

* 未闭合图表围栏：仍由 `_protect_chart_fences` 处理（不双重删除）

* 已验证：闭合 mermaid 块、闭合普通块、未闭合 mermaid 块三种场景均正确



***

### BUG-2："数字 + 空格 + 中文标题" 不被识别为 L3 标题（P1）

**现象**：AI 偶尔输出 "1 施工准备"（数字 + 空格，无顿号 / 句点）格式的标题，不匹配任何七级编号模式，整行被拍平为普通段落，标题层级和编号样式在导出文档中全部丢失。

**根因**：



* L3 模式原正则：`^(\d+)(?!\.\d)\s*[、．.]\s*(.+)$`

* `[、．.]` 是**必需**分隔符，数字 + 空格（无标点）不匹配

* AI 实际输出中 "1 标题" 格式很常见

**实测验证**：



```
"1、施工准备"  → L3 ✅
"1. 施工准备"  → L3 ✅
"1 施工准备"   → None（拍平为段落）❌  ← BUG
"1.1 总体方案" → L4 ✅
```

**修复方案**：



* 文件：`app/services/content_cleaning.py`

* 修改 L3 模式正则为：



```
re.compile(r"^(\d+)(?!\.\d)(?:\s*[、．.]\s*|\s+(?=[一-鿿]))(.+)$")
```



* 分隔符改为二选一：顿号 / 句点 **或** 空格 + 中文标题

* 空格分支用 lookahead `(?=[一-鿿])` 锚定中文字符开头

**误匹配防护**：



* "1 000 元"（空格后是数字）→ 不匹配 ✅

* "2 500 人"（空格后是数字）→ 不匹配 ✅

* 七级其他层级（L1/L2/L4/L5/L6/L7）→ 不受影响 ✅

## 九、遗留问题与后续建议

### 9.1 已知限制（非 BUG）



1. **列表 vs 标题歧义**："1. xxx" 在 Markdown 中既可是有序列表项也可是 L3 标题。系统选择七级编号标准（视为标题），这是标书场景的合理取舍。

2. **SSE 进度精度**：流式生成无法预知 AI 完成时间，当前用心跳保活 + 固定 50% 进度，属于工程折中。

3. **并发同项目导出**：图号计数器在进程级共享，同项目并发导出会互串。当前由上游任务组锁保证同项目同时只有一个导出。

### 9.2 后续建议



1. **提示词强化**：在 `build_chapter_content_messages` 中明确要求 AI 使用 "1、" 或 "1." 格式，减少 "1" 格式输出（虽然代码层已兼容，但提示词约束更根本）。

2. **监控指标**：在 SSE 事件中增加 "围栏坏块删除次数" 和 "编号补识别次数"，便于后续观察 AI 输出质量。

3. **sse\_content.py 重构**：3351 行单文件过大，建议按 generate/expand 拆分为两个模块。
