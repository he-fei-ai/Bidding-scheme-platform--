## 2. 功能架构与现状分析（按维度）

### 2.1 上传
- 命名空间隔离：`enforce_project_access(project_id)`（`routers/files.py:32`），无越权。
- 落盘：以 `file_id` 落盘，`MAX_FILE_SIZE=50MB` 分片读取（`routers/files.py:61-73`），`ALLOWED_EXTENSIONS` 由 `SUPPORTED_EXTENSIONS` 派生（`routers/files.py:27`），前后端扩展名集合一致。

### 2.2 格式识别
- 双轨：扩展名 + 魔数。OLE2 复合文档额外走 `_extract_legacy_ole_chain`（`services/files.py:765-860`），按扩展名分派 doc/xls/ppt，未命中走 `_extract_doc` 通用回退。
- 非 OLE 文件带错误扩展名会跳过 OLE2 链（`test_import_fixes_2026_10_06.py:193 test_non_ole_file_with_wrong_ext_skips_chain`）。

### 2.3 内容解析
- 覆盖 docx（python-docx）、pdf（pdfplumber + MinerU 懒加载，`services/files.py:1066 _mineru_parser_instance`）、doc（antiword/catdoc）、xlsx（openpyxl）、pptx、ppt（COM）、html、wps、图片 OCR（MinerU/PaddleOCR/Tesseract 三引擎，`_ocr_with_mineru:1571`）。
- 编码异常：`_read_text_auto` 多编码探测；空文本返回 `EMPTY_TEXT_MESSAGE` 并从合并文本中剔除（`is_extraction_notice`）。

### 2.4 信息保存与分类
- 主/附互斥：新主文件把旧主降级为 supporting（`save_upload`）。
- 删除主文件：自动升级某 supporting 为主文件，返回 `promoted_file_id`（`delete_file:2276`，前端据此更新状态条）。
- 角色切换：`update_file_role` 互斥约束、返回 `demoted_file_ids`。

### 2.5 错误处理
- 解析失败写入 `message`，状态置 `failed`/`empty`；批量状态条在 `FileUploadPage.tsx` 汇总（总文件数/成功/失败/处理中）。

### 2.6 工作流程 / AI 调用
- 同步解析 + 异步 OCR/MinerU（celery 或 inline 降级）。
- 要点提取：`generate_facts` 优先事实文件文本 → 招标全文回退；AI 失败回退 `_generate_default_facts` 启发式（`routers/facts.py`）。

### 2.7 数据链与存储 / 路由与接口
- 存储：文件落盘 + 元信息入库（`get_project_files`）。合并文本进程级缓存 `_text_cache`。
- 路由：`POST /api/v1/projects/{id}/files`（上传）、`GET .../files`（列表）、`GET .../files/{fid}/text`（单文件）、`GET .../latest-text`（合并）、`POST .../files/{fid}/re-extract`、`POST .../files/{fid}/async-reparse`、`POST .../files/{fid}/role`、`DELETE .../files/{fid}`；要点提取 `GET/POST .../facts`、`POST .../facts/generate`、`POST .../facts/confirm`、`POST .../facts/audit`。

### 2.8 容错 / 缓存 / 并发 / 日志 / 配置 / 测试
- 容错：PPT COM 超时护栏（120s）+ 守护线程；PDF/图片解析异常被捕获并记入 `message`。
- 缓存：合并文本 `_text_cache`，失效点在 `save_upload`/`delete_file`/`re_extract_text`。
- 并发：`save_upload` 持项目锁防竞态；`_text_cache` 用 `threading.Lock`。
- 日志：`logger` 结构化记录解析结果/降级原因。
- 配置：`MAX_FILE_SIZE`、`PPT_COM_ENABLED`、`PPT_COM_TIMEOUT`、`OCR_ENGINE`、`OCR_FALLBACK_ENGINES` 等（见 §5 新增配置说明）。
- 测试：后端 190+ 用例覆盖并发/跨模块/角色/状态线；前端纯函数 + DOM 组件测试（见 §6）。

## 5. 修复项清单（BUG）

### 5.1 修复 B1：MinerU 单例测试顺序依赖（测试隔离 BUG）
- **现象**：完整导入套件中 `TestMineruSingletonModuleLevel.test_mineru_parser_instance_is_module_level` 断言 `_mineru_parser_instance is None` 失败——因同进程内其他用例已触发图片 OCR，进程级懒加载单例被置为真实实例。
- **根因**：断言依赖用例执行顺序，单测不隔离。
- **修复**：断言前显式复位 `files_module._mineru_parser_instance = None`（`tests/test_import_fixes_2026_10_08.py`），不改变生产懒加载语义。
- **验证**：修复后该用例通过（见 §6 基线对比）。

### 5.2 修复 B2：PPT COM 原生崩溃（容错 BUG，部分修复）
- **现象**：无可用 PowerPoint 时 `win32com.client.Dispatch("PowerPoint.Application")` 触发原生访问违规（`Windows fatal exception: code 0x800706be/0x800706ba`），在守护线程打印堆栈。
- **根因**：原代码仅以 `sys.platform=='win32' and PPT_COM_ENABLED` 判断是否尝试 COM，未探测 Office 是否真正可用；COM RPC 失败在部分机器表现为不可被 `except Exception` 捕获的原生 AV。
- **修复**：新增 `_ppt_com_available()`——开关关闭/非 win32 直接返回 False；否则探测 `pywin32` 可导入 + 注册表 `HKEY_CLASSES_ROOT\PowerPoint.Application` 是否存在，结果进程内缓存（`services/files.py`）。`_extract_ppt` 改用之（`routers`→`services` 调用链不变）。
- **协调测试**：`test_import_enhancements_2026_10_05.py` 的 `test_timeout_falls_back_to_hint`/`test_success_path_returns_text` 增加 `monkeypatch.setattr(files_mod,"_ppt_com_available", lambda: True)`，确保无 Office 的 CI 仍走到真实超时/成功路径。
- **边界说明**：本机存在 Office 注册表但无可用 PowerPoint 二进制时，注册表探测通过、仍可能触发原生 AV；该场景由既有超时护栏（`PPT_COM_TIMEOUT` + 守护线程）兜底，进程不崩、测试不挂。**此为改动前已存在噪声**，本轮未做更激进的规避（强行禁用 COM 会破坏 `test_success_path_returns_text`）。
- **验证**：套件仍 190 passed / 1 skipped；原生崩溃仅在「注册表残留」机器出现且被含时护栏兜住（详见 §6）。

### 5.3 修复 B3：跨模块数据链调用链校验（缺失测试 → 视为潜在断裂风险）
- 详情见 O1：新增回归测试锁定 `上传解析产物` 能被 `要点提取` 正确消费（事实文件优选命中、全文回退完整、删除后缓存失效无脏读）。属「调用链路贯通」加固。

### 5.4 修复 B4（遗留项 TD-A 最优加固）：PPT COM 改为独立子进程隔离（彻底消除原生崩溃）
- **现象**：无可用 PowerPoint 时 `win32com.client.Dispatch("PowerPoint.Application")` 触发原生访问违规（`Windows fatal exception: code 0x800706be/0x800706ba`）。本轮初版仅加注册表探测，对「注册表残留但无可用二进制」机器仍会在父进程 stderr 打印原生崩溃堆栈（进程不崩、测试不挂，但属噪声）。
- **最优方案**：原生访问违规是**进程级**崩溃，线程无法隔离（线程里会拖垮整个 Python 进程）。改为在**独立子进程**中执行 COM 提取：
  - `services/files.py` 新增 `_ppt_com_child_target`（子进程入口，将 fd 1/2 重定向到 `devnull` 并 `faulthandler.disable()`，彻底消除父进程控制台噪声）+ `_ppt_com_terminate`；
  - `_ppt_via_powerpoint_com` 由 `threading.Thread` 升级为 `multiprocessing`（`spawn`）子进程，`join(PPT_COM_TIMEOUT)` 上界约束；超时/原生崩溃只杀子进程，父（解析）进程始终返回 `""` → 由 `_extract_ppt` 转降级提示，**绝不挂死 / 崩溃 / 污染控制台**。
  - 测试钩子（仅测试用，生产绝不设置）：`PPT_COM_INJECT_RESULT`（子进程直接返回文本）、`PPT_COM_INJECT_HANG`（子进程睡眠 60s 验证超时护栏）。跨进程 monkeypatch 不生效，故 `TestPptComGuardrails` 两用例改为 `monkeypatch.setenv(...)` 注入。
- **验证**：导入+要点提取全套件 **274 passed / 1 skipped**，且 stderr 中 `fatal exception` **计数 = 0**（此前为 3），注册表残留机器的原生崩溃噪声已彻底消除。无回归。
