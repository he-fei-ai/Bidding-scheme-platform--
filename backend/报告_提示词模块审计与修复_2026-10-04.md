## 二、功能清单 / 相关代码 / 依赖 / 调用方 / 风险点

### 2.1 模块组成

| 层 | 文件 | 职责 |
|----|------|------|
| 注册表 | `app/services/ai/prompts/_registry.py` | `_reg()` 注册、变量提取 `extract_variables`、统一渲染 `render_prompt`、共享规则解析 `_resolve_shared`、清洗 `clean_prompt_text` |
| 运行时缓存 | `app/services/ai/prompts/_cache.py` | DB 优先 / 硬编码回退、失败冷却、线程安全、`get_prompt`/`get_prompt_with_validation`/`reload_prompt_cache` |

### 2.2 依赖模块与调用方（get_prompt 消费点）

- 目录：`workflows_outline_v51.py`（L1/L2/selfcheck/direct）、`workflows_outline_utils.py`（L3 修复）、`workflows_quality.py`（目录审核）
- 正文/编排：`workflows_sections.py`（章节 system / 续写）、`workflows_orchestration.py`（内容编排 user 模板）
- 图表：`image_engine.py`（多类图表 system + `CHART_DATA_FIX`）、`mermaid_*`
- 其它：`workflows_base.py`（`JSON_REPAIR_PROMPT`）、`knowledge.py`、`rejection.py`、`industry_tree.py`、`consistency_repair.py`
- 前端 PromptEditorPage 经 `/prompts*` 调用（已统一注入 token）

### 2.3 风险点

1. 提示词正本与调用点分离——调用点若绕过 `get_prompt` 直接引用常量，则管理页 DB 编辑失效。
2. 变量注入存在三套机制（`render_prompt` / `_fill_template` / 裸 `str.replace`），口径不一致易致占位符泄漏或告警噪声。
3. `get_prompt` 的变量校验历史依据注册表默认，与 DB 实际生效内容脱节。
4. 多进程部署时 prompt 缓存无跨进程失效通道（仅同进程 reload）。

## 三、缺口清单与技术债清单（含影响范围与优先级）

| 编号 | 类型 | 描述 | 影响范围 | 优先级 | 本轮处置 |
|------|------|------|----------|--------|----------|
| B-1 | 功能缺口/BUG | `generate_outline_direct` 直接 `from .prompts.outline import` 硬编码常量 + `str.replace` 注入，**绕过 get_prompt 的 DB 优先缓存** | 短标书直出目录：管理页对 `OUTLINE_DIRECT_SYSTEM/USER` 的编辑完全不生效；且只认 `__UPPER__`，用户改 `{var}`/大小写即占位符泄漏 | P1 | ✅ 已修复 |
| B-2 | 技术债 | L3 标题修复 `get_prompt(key)` 取模板后用裸 `.replace("__X__")` 注入，与统一渲染不一致；无 kwargs 触发缺失变量噪声 | 目录 L3 修复链：DB 编辑生效但注入口径不统一、日志噪声 | P2 | ✅ 已修复 |
| D-3 | 技术债/BUG | `get_prompt` 变量校验用 `validate_prompt_variables(key)` 恒校验**注册表默认模板**，BUG-FIX-28 注释声称「统一校验」实未覆盖 DB 编辑场景 | 全热路径：DB 新增占位符漏检、DB 删除占位符每次误报告警 | P2 | ✅ 已修复 |
| D-1 | 技术债 | `routers/prompts.py._default_variables` 注释声称「缓存」但函数体每次重新解析 | 保存校验路径性能/一致性 | P3 | ✅ 已修复 |
| D-4 | 技术债 | 多进程部署 prompt 缓存无跨进程失效（靠同进程 reload / 重启） | 生产多 worker 下编辑后其它 worker 短暂用旧值 | P3（遗留） | ⚠️ 记录建议 |
| D-5 | 技术债 | 变量注入仍有 `_fill_template`（`workflows_quality` 目录审核）机制，未并入 render_prompt | 目录审核链，行为正确但口径不统一 | P3（遗留） | ⚠️ 记录建议 |
| D-6 | 健壮性 | 前端 `/prompts/${key}` 未 `encodeURIComponent`；后端 PUT 接受未知 key 成孤儿行（列表不显示、reset 404） | 极端边界，key 均为大写常量名，实际不触发 | P3（遗留） | ⚠️ 记录建议 |

> 关于「敏感信息脱敏 / 提示词注入防范」：提示词读接口已于 2026-09-29 补统一鉴权；保存前校验未注册 `{shared:NAME}` 引用与关键占位符删除（可 force 跳过）；`prompt_versions` 归档仅存内容与 `changed_by` 用户名，无密钥类敏感字段。本轮未发现新的泄露面，无需改动。

## 四、修复项 / 优化项清单（文件路径 + 关键函数）

- 文件：`app/services/ai/workflows_outline_v51.py`

- 配套：模块头 `from .prompts import get_prompt, render_prompt`（新增 render_prompt）。

### B-2｜L3 修复统一 render_prompt（P2）
- 文件：`app/services/ai/workflows_outline_utils.py`

- 改动：`repair_template = get_prompt("L3_TITLE_REPAIR_PROMPT")`（取未渲染模板，命中 DB），逐任务 `render_prompt(repair_template, L1_TITLE=..., L2_TITLE=..., L3_TITLE=..., PROJECT_CONTEXT=...)` 替代 4 次裸 `.replace`。

### D-3｜变量校验按实际生效内容（P2）

## 六、遗留问题与后续建议

1. **D-4｜prompt 缓存跨进程失效**：多 worker 部署时管理页编辑仅 reload 当前进程。建议仿 `ai_config_state.ai_config_version` 引入版本计数器 + 短 TTL 防抖，`get_prompt` 命中前比对库内版本触发重载。
2. **D-5｜统一 `_fill_template`**：目录审核（`workflows_quality._build_outline_review_texts`）仍用「首次数据 + 标签回退」专用机制。功能正确但与 `render_prompt` 双轨，建议评估合并到统一渲染并保留「同占位符多次出现」语义。
3. **D-6｜路由健壮性**：前端路径参数 `encodeURIComponent`；后端 PUT 对未知 key 拒绝或登记，避免孤儿行（列表不显示、reset 404）。
4. **导出侧 2 个失败**：转交「导出文档模块」跟进渲染失败时的图注/编号回退（非本模块范畴）。
5. **可观测性增强（建议）**：为 `render_prompt` 的 unresolved 告警接入指标计数，配合提示词管理页展示「运行时变量命中率」，把当前仅日志的校验闭环为可视化监控。
