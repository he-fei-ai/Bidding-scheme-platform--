## 二、功能清单与相关代码

### 2.1 功能清单（生成大纲模块）

1. **三级目录树生成（V5.1 工作流）**：L1（AI 生成一级目录）→ L1 审核 → L2（代码预构建骨架 + AI 并发填充二级/三级）→ L2 审核 → L3 串行后处理 → AI 语义自检 → 门禁（gate）→ 最终审核 → `renumber_outline_ids` 统一编号。
2. **直出路径**：`generate_outline_direct`（一次性直出整树，与分步路径共用清洗/门禁/落库链）。
3. **脏标题治理**：`_is_dirty_l2_title_deep` / `_is_dirty_l3_title_deep` 判脏 → `_cleanup_placeholder_titles` 清洗（剥前后缀保主体 → 「之N」中文序数消歧 → `_semantic_fallback_title` 语义重写）→ `_uniquify_outline_titles` 同级唯一化。
4. **落库安全网**：`sse_db_ops._fill_or_fix_outline_titles(fix_dirty)` + `_clear_and_save_outline`——顺序严格「先剥编号 → 再去重 → 最后清占位」，复用同一清洗器。
5. **编号体系**：`child_number` 单一拼接实现（id / DB path / 版号同源，2026-10-13 统一）；`outline_numbering.py` 模板引擎（配置 `OUTLINE_NUMBERING_ENABLED` 默认 **false**，gate 可选写 number 字段）；导出显示权威为 `heading_standard.DEFAULT_NUMBERING_TEMPLATES`（V3.1 七级：第{zh}节 / {zh} / {num} / {full} / {full} / {num}） / {alpha}）。
6. **SSE 分步推送与断线重连**：`_NotifyQueue` 广播链 + `event_emitter=_qput` + task_registry 重连（`sse_outline.py` L317-331 事件透传、L1183 主流程接线）。
7. **前端目录编辑器**：`OutlineEditorPage.tsx` 事件链处理进度/降级/审核/完成事件，树编辑回写走同一条落库安全网。

## 四、探查结果与根因结论（t2/t4）

### 4.1 用户症状根因链（闭环）

1. **全链 grep 证实代码零追加「（N）」**：后端/前端不存在任何主动追加冲突后缀的代码路径；「(2)/(3)」后缀只能来自 **AI 原始产出**，且到达 DB 前已被三道防线拦截（判脏→清洗→落库安全网），DB 实况干净。
2. **「大量占位泛化三级标题」的真实现网来源 = L2 降级 + 用户无感**：L2 AI 填充失败（日志实证 429/超时）→ `_default_l2_children_for_skeleton` 模板默认目录兜底 → 诊断只进后端日志（`l2_degraded` 在 routers 层零匹配）→ **前端看到的是一份「生成成功」但标题泛化的目录树**。这就是「用户拿到泛化目录却不知道原因」的透知缺口。
3. **提示词层无编号残留禁令**：L1/L2/SELF CHECK/DIRECT/REVIEW 提示词均未禁止 AI 把编号写进标题文本 → AI 偶发产出「总体实施策划（2）」作 L1/L2 章名。
4. **L1 层清洗缺口**：`_cleanup_placeholder_titles` 旧实现 `level >= 2` 把一级完全排除——脏 L1 章名一路穿过 L1 审核、骨架锚定直到落库，且其**整棵子树的清洗都以脏标题作语义源**。

### 4.2 其余探查结论（无需修复项，代码依据）

- **编号命名空间统一性**：id 由 `child_number` 单一拼接实现（2026-10-13 已统一 id/DB path/版号）；模板引擎经 `OUTLINE_NUMBERING_ENABLED`（默认 false）由 gate 可选写 number 字段——关闭时行为与历史完全一致（向后兼容）；导出显示以 `heading_standard` V3.1 七级为权威；前端 `computeHeadingCounters` 位置派生。三套各司其职、无活跃漂移。
- **正文子标题编号冲突（双重编号）**：正文提示词要求「目录 1.2.3 → 正文小标题 1.2.3.1 递增」（`workflows_sections.py` L1552）；`content_cleaning.HEADING_PATTERNS` L91 把 **≥3 段点分编号**（1.2.3 / 1.2.3.1）一律归为 L5 并保留 `raw_line`；导出端 L1566 对 rel_level≥5 **原样渲染不重编号**，L1-L4 则先 `_strip_heading_numbering`（L1580）再补确定性编号 → **不存在双重编号缺陷**。
- **分步生成状态/并发**：`_merge_filled_children` 按顺序映射 + `check_json` + `_check_titles_filled` 空标题 raise；补偿重跑 `l2_retry_rounds` 救回后不计入降级——状态机自洽。
