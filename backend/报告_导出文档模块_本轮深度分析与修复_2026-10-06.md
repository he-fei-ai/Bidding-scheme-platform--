## 4. 修复项（代码方案 / 文件 / 关键函数）

### GAP-A 写盘原子化 —— `backend/app/services/export.py::build_docx`

**修复前**：`doc.save(output_path)` 直写最终路径。docx 打包是完整 XML 序列化+ZIP 写盘，
中途失败（磁盘满/权限/异常）会在 exports/ 留一个截断损坏的 .docx。

**修复后**（export.py 约 2917-2945）：
```python
tmp_save_path = f"{output_path}.tmp.{os.getpid()}"
try:
    doc.save(tmp_save_path)
    if os.path.getsize(tmp_save_path) == 0:
        raise RuntimeError("临时文件大小为 0，拒绝原子替换")
    os.replace(tmp_save_path, output_path)
except Exception:
    # 清理残留 .tmp，再 raise
```
与本文件 `_save_export_cache_index` 的"临时文件+os.replace"同口径。
**零配置项、零接口变更、向后兼容**：只改变写盘方式，输出文件路径/内容/记录均不变。

### GAP-B 前端组件测试 —— 新增 `frontend/src/pages/ExportConfigPage.dom.test.tsx`

4 例组件级（DOM）交互测试，按 ConsistencyPage 既有范式（vi.mock api + matchMedia shim）：
1. 挂载渲染「完整性检查 / 导出 DOCX」主按钮；
2. 点「完整性检查」→ `checkDocument` 被调、strictMode 透传、渲染"通过"；
3. 点「导出 DOCX」→ **优先走 SSE 流**（`exportDocxStream`）且配置携带 `preset_id`、
   成功后渲染"下载文档"、**不降级**重跑同步接口；
4. 导出历史记录渲染。
