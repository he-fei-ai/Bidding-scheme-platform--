## 1. 整体架构

易标是一款**本地桌面投标工具**：所有 AI 调用、任务编排、数据落库都发生在用户机器上，不依赖中心服务端（分析埋点除外）。

```
┌──────────────────────────────────────────────────────────────┐
│  Renderer (React 19 + TS 5.9 + Vite 7)                         │
│  通过 window.yibiao (preload 暴露的 IPC 桥) 调用主进程能力       │
└───────────────┬────────────────────────────────────────────────┘
                │ IPC (contextBridge)
┌───────────────▼────────────────────────────────────────────────┐
│  Electron Main（CommonJS .cjs，任务/服务真正执行处）             │
│  ├─ services/*.cjs   业务服务（AI、任务、导出、知识库、生图）     │
│  ├─ 耗时任务在 Main 后台运行，支持暂停/恢复/断点续跑             │
│  └─ doc2markdown/*.mjs  ESM 转换引擎（动态 import 桥接）         │
└───────────────┬────────────────────────────────────────────────┘
                │ better-sqlite3
┌───────────────▼────────────────────────────────────────────────┐
│  本地 SQLite（技术标目录节点/正文/事实/配图计划/解析条目等）      │
│  + 配置文件（AI Provider、模型参数）                            │
└────────────────────────────────────────────────────────────────┘
        + openxmlhelper（.NET 10 Word 导出）
        + analytics（Cloudflare Worker 埋点）
        + Pi Agent（opencode 风格运行时，承载目录/事实/配图/Agent修复）
```

**关键设计取向**（依据 `README.md`）：
- 耗时任务在 Electron Main 后台运行，天然支持"关了窗口回来继续"的恢复语义；
- 数据以本地 SQLite 为单一事实来源，配置以文件为准；
- 复杂"多轮/有状态"的任务（目录、全局事实、配图编排、Agent 修复）交给 **Pi Agent** 状态机，用文件（工作目录里的 JSON/MD）作为 Agent 与主进程之间的契约，而非一次性 prompt。

## 2. 六步主工作流

依据 `全功能模块.txt`（340 行，6 模块功能规格母版）与 `.workbuddy-ai/reports/` 各模块深度报告，易标产品链路为固定 6 步：

| 步骤 | 名称 | 关键产物（SQLite 表 / 文件） | 深度报告 |
|------|------|------------------------------|----------|
| STEP01 | 选择标书 / 文档→Markdown | 招标全文 Markdown | 解析提取模块深度探索报告 |
| STEP02 | 招标文件解析（18 项，6 必填） | `technical_plan_bid_items` | 招标文件解析模块深度探索报告 |
| STEP03 | 目录生成 | `technical_plan_outline_nodes` | 目录生成模块深度探索报告 |
| STEP04 | 全局事实 | `technical_plan_global_fact_groups` | 全局事实模块深度探索报告 |
| STEP05 | 正文生成（含配图/一致性） | `technical_plan_content_sections` / `content_plans` / `illustration_plans` | 正文生成模块深度探索报告 |
| STEP06 | 导出 / 扩写 | DOCX（openxmlhelper） | — |

三步"AI 前置产物"环环相扣：**STEP02 解析条目 → STEP03 目录 → STEP04 全局事实 → STEP05 正文**，下游每一步都复用上游的结构化产物（详见"文件信息提取汇总引入报告"）。

## 3. 技术栈（依据 `README.md`，373 行）

| 层 | 技术 |
|----|------|
| 桌面壳 | Electron 41+（Main/Preload/Renderer） |
| 前端 | React 19+ / TypeScript 5.9+ / Vite 7 |
| 主进程 | Node.js，CommonJS `.cjs`（业务/任务） |
| 转换引擎 | ESM `.mjs`（`doc2markdown/convert.mjs` 等），主进程用动态 `import()` 桥接 |

| Agent 运行时 | Pi Agent（opencode 风格），承载多轮有状态任务 |
| 埋点 | Cloudflare Worker（`analytics/`） |
| 许可 | AGPL-3.0 |

本地开发：`cd client && npm ci && npm run dev`（README「快速开始」）。

## 8. 结论（均附文件依据）

1. 易标是本地优先的 Electron 桌面工具，AI 与任务全在主进程后台运行并可恢复（`README.md`）。
2. 产品为固定 6 步链路，STEP02→03→04→05 结构化产物逐级复用（`全功能模块.txt` + `.workbuddy-ai/reports/*`）。
3. 有状态多轮任务（目录/事实/配图/Agent修复）统一用 Pi Agent + 工作目录文件契约实现（`outlineGenerationTaskV2.cjs`、`globalFactsTaskV2.cjs`、`contentIllustrationPlanning.cjs`）。
4. 弱模型稳定输出靠"JSON Schema 约束 + 语法/Schema/业务三级校验 + JSON 修复 + 重试 + 分步拆分 + 审核回灌 + 二次生成"闭环（`aiService.collectJsonResponse`、目录 Schema 族）。
5. 缓存成本优化贯穿全链路："大且稳定上下文前置、任务差异放最后"（`bidAnalysisTask.cjs` 预热、`contentGenerationTask.cjs` 编排/正文消息顺序）。
6. 短板：正文核心文件 6759 行无测试；解析报告仅部分自带；无建筑工程垂直能力。
