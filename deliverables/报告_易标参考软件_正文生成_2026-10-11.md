## 2. 生成思路（逐叶子 + 并发 + 上下文 + 去重 + 字数）

- **按叶子节点逐节生成**：仅 `content_mode==='ai-generate'` 且需生成的叶子进正文流程；`template-fill`/`point-to-point` 走填充。
- **并发**：文本并发 `= 10`，图片并发 `= 2`（自带报告常量）；预热 key `${restored|normal}:${table|plain}`。
- **上下文传递与去重**：每节生成注入上级/同级摘要，`stripRepeatedChapterTitle` 去重复标题；编排 `writing_focus` 聚焦当前节避免越界。
- **字数控制**：`GENERATION_WORD_TARGET_RATIO=0.8`；节区间 `[0.8S, 1.2S]`；`MAX_WORD_ADJUSTMENT_ROUNDS=3`、`TOTAL_WORD_ADJUSTMENT_BATCH_SIZE=10`；`DEFAULT_SECTION_WORD_GUIDANCE=3000`。
- `CONTENT_PLAN_VERSION=4`、`ILLUSTRATION_PLAN_VERSION=3`。

## 3. 工作流程（收集叶子→编排→并发生成→配图→审核）

```
收集叶子节点
  → 正文编排 buildChapterContentPlanMessages（判 知识库item_ids / facts.titles / table.needed / writing_focus）
  → 并发生成正文 buildChapterContentMessages（16 条硬规则，并发 10）
  → 表格清理（TABLE_CLEANUP_BATCH_CHAR_LIMIT=30000，表格转普通文字）
  → 字数调整 buildWordAdjustmentMessages（expand/shrink，锚点逐字唯一）
  → 配图阶段（预编排 illustration-plan + 生成 html/ai/mermaid）
  → 一致性审计 buildConsistencyAuditMessages → 修复（普通/Agent）
  → 原方案覆盖审计 buildOriginalCoverageAuditMessages
```

### 3.1 正文编排（编排判什么）
`buildChapterContentPlanMessages`（`contentGenerationTask.cjs:793`）system="投标技术方案正文编排助手"，返回 JSON：
```json
{ "writing_focus": "...", "knowledge": {"item_ids": [...]}, "facts": {"titles": [...]}, "table": {"needed": true, "purpose": "..."} }
```
消息顺序（缓存最优）：**知识库轻量条目 → 招标文件关键信息 → 全局事实标题清单 → 上级章节 → 同级章节 → 额外要求 → 当前章节任务**。

### 3.2 正文生成 16 条硬规则（节选，`contentGenerationTask.cjs:888`）
朴实无华不要假大空；不用奇怪连接词避免 AI 味；严禁 Markdown 标题 `#`；严禁 Mermaid/PlantUML/Graphviz（配图系统另行处理）；全局事实优先不得矛盾；未提供不编造人员/周期/质保/品牌/型号；表格受编排 `table.needed` 管控；不生成标题直接返回正文。

### 3.3 配图阶段（三类，html>ai>mermaid）
- 预编排 `buildIllustrationPlanningPrompt`（13 规则）产出 `illustration-plan.json`：`{items:[{kind, image_type, title, section_ids, placement, priority}]}`；`resolveIllustrationPlan` 严格校验（title≤20 字无"图:"前缀、priority 1-5、section_ids 存在且唯一、html 多节须同父连续、kind 顺序 html→ai→mermaid + priority 降序 + 目录序，occupied 互斥）。
- 生成（`contentIllustrationGeneration.cjs`）：`buildAiImagePrompt`（专业实景/工程图示，少字克制）、`buildHtmlAgentPrompt`（≥24px、≤12 节点、禁旋转重叠）、`buildMermaidGenerationMessages`（仅 flowchart TD/TB/LR/RL/BT，中文标签双引号，无分号无 & 简写，≤12 节点 ≤16 字，无代码围栏）。
- **Mermaid 校验闭环**：`assertMermaidPreviewCompatible`（正则：禁分号/禁 & 简写/中文标签须双引号/中文 ID 禁止）→ `validateMermaidRender`（本地渲染出 PNG）→ 失败进 `prepareRenderableMermaid` 修复循环（`MERMAID_REPAIR_ATTEMPTS`）。

### 3.4 审核阶段
一致性审计 → 冲突修复 → 原方案覆盖审计（covered/partial/missing/conflict，conflict 只报告不修）。

## 5. 校验与修复（一致性审计 / 普通修复 / Agent 修复）

- **全文一致性审计**：`CONSISTENCY_AUDIT_GROUP_WORD_LIMIT=300000` —— 按 30 万字分组送审，只报"已明确写出且与全局事实冲突"的项。
- **普通修复**：`CONSISTENCY_REPAIR_MAX_ATTEMPTS=2`；补丁为 `old_text/new_text`，`findContentExpansionTargetTextMatch` 先精确后按行 trim，**拒绝多处命中**；`applyContentExpansionPatch` insert/replace 带 anchor start/end；`validateWordAdjustmentOperations` 唯一精确命中否则抛错（唯一命中才替换，绝不误伤）。
- **Agent 修复**：opencode/Pi Agent 风格——准备文件、搜索关键词、分段读取、多轮修改、程序校验回写（自带报告 D1）。
- 表格→文字：`normalizeTableCleanupResponse`/`validateTableCleanupResponse`（`:756`），逐 `table_id` 处理，`replacement_text` 禁含表格/HTML/标题。
