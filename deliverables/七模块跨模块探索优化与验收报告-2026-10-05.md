### 2.2 已定位并修复的断点/不一致

1. **接口形态不统一（M2）**：`GET /ai/analysis` 在「analysis 行存在/不存在」两种状态下键集不同（缺 `global_facts_items` / `facts_policy`），消费方按有行形态读键会 `KeyError`。→ 2026-09-29 已补齐，本次以契约测试固化。
2. **策略漂移（M2→M4）**：Step02 评分流程自动提取事实永远按 `fabricate` 运行，用户选的 `omit`/`placeholder` 不生效。→ 2026-09-29 已把策略透传到 `analysis.facts_policy`。
3. **占位符泄漏（M4→M5）**：placeholder 策略下「【待填写】」经 Celery 路径直接注入正文。→ 已统一到 `facts_service.facts_for_generation`。

## 三、修复项清单（本次实际修改）

### F-1 【安全/P1】`ai.py` SQL 标识符未校验（注入模板 + 幻影列 500）

- **文件**：`backend/app/routers/ai.py`
- **函数**：`_sync_confirm_field`（原 115–117 行）、`_sync_insert_or_update`、`_sync_confirm_and_retrieve`
- **根因**：两处把「确认标记列名」直接 f-string 插进 SQL 标识符。
  - `_sync_confirm_field` **完全没有**校验（`_sync_update_field` / `_sync_select_flags` 都有 `_validate_field_name`，唯独此处没有）；
  - `_sync_confirm_and_retrieve` 只校验了 `field` 本体，**未校验由其派生的 `confirmed_col`**；派生规则是 `f"confirmed_{field.replace('_json','')}"`，对合法字段 `scope` / `facts_policy` 会产出库里**不存在**的列名 `confirmed_scope` / `confirmed_facts_policy`，拼进 SQL 直接 500。
- **影响**：现有调用方传字面量，暂无可利用路径，但属「已校验字段名 → 拼进 SQL 标识符」模板，新增调用方一旦透传 `body.field` 即为直接 SQL 注入；且属潜伏 500。
- **修改**：新增 `_ALLOWED_CONFIRMED_FIELDS` 白名单 + `_validate_confirmed_field()` + 显式映射 `_FIELD_TO_CONFIRMED` + `_derive_confirmed_field()`（映射不到即返回 `None`，调用方跳过 confirmed 列写入，SQL 分两支）。
- **验证**：`test_confirm_field_rejects_injection`、`test_derive_confirmed_field_no_phantom_column`、`test_confirm_and_retrieve_no_phantom_column`、`test_insert_or_update_no_phantom_column`、`test_insert_or_update_resets_confirmed_flag`（5 项）

### F-2 【缺陷/P2】`export.py` SSE 流式导出路径越界静默降级（漏改副本）

- **文件**：`backend/app/routers/export.py`（原 253–255 行）
- **根因**：同步导出路径在 2026-09-18 已修复「死代码」越界判定（154–160 行，越界 → 拒绝返回），但**并行副本**——SSE 流式路径 `_run_build` 内——当时漏改，仍是：
  ```python
  try: rel_path = str(Path(output_path).resolve().relative_to(PROJECTS_DATA_DIR.resolve()))
  except ValueError: rel_path = Path(output_path).name   # 越界被静默降级成裸文件名
  ```
  异常分支既无 `return` 也无拒绝语义，越界路径不会被拦截，只是白算一次。
- **影响**：`completed` 事件的 `file_path` 可能是脱离项目数据目录的裸文件名；下载端虽有二次校验，但流式路径的产物落点不再可信。
- **修改**：与同步路径同口径——越界即 `raise ValueError`，由 `_run_build` 的 `except` 统一 emit `error` 事件并回滚步骤（`update_step(5)`），不产生伪造的 `completed` 事件。
- **验证**：`test_sync_path_rejects_out_of_bounds`、`test_stream_path_guard_logic` + E2E 脚本 M7 全段

### F-3 【技术债/P3】`sse_utils.py` 事实解析第二份副本

- **文件**：`backend/app/routers/sse/sse_utils.py`（原 85–95 行）
- **根因**：`_parse_global_facts_items` 自己写了一遍「解析 + 剔除占位」的 list 推导式，而 `facts_service.facts_for_generation()` 已有正本（Celery 侧共用）。注释声称「整体委派」，实际只委派到了 `parse_stored_items` + `is_placeholder_value` 两个原子函数，组合逻辑仍是副本。
- **影响**：占位判定口径变化（如新增占位前缀）时两边会再次漂移，重新产生「前端有事实、正文没注入」或「占位串进标书正文」两类缺陷。
- **修改**：`kept = facts_for_generation(raw)`，仅保留 drop 日志（需先取原始条数算过滤量）。`is_placeholder_value` 保留导入——它是被 `test_facts_module_interactions.py::test_sse_reader_shares_the_canonical_parser` 显式断言的单一正本再导出（本次踩到该断言后已恢复）。
- **验证**：`test_sse_path_and_celery_path_agree`、`test_placeholder_filtered` 等 5 项

### F-4 【契约固化】新增跨模块回归测试

- **文件**：`backend/tests/test_cross_module_fixes_2026_10_05.py`（新增，16 项）
- 覆盖 F-1/F-2/F-3 的复现与修复，外加 `TestAnalysisContract::test_get_analysis_shape_stable`（M2 无行/有行键集一致性的端到端契约测试，走真实 `TestClient`）。

### F-5 【验收工具】端到端验收脚本
