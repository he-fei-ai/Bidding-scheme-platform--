### 2.2 数据流（读取链路）

```
HTTP 请求 → routers/ai_config.get_ai_config()
         → provider_factory.get_ai_config()
             ├─ 进程内缓存（_ai_config_cache，TTL 1h）
             │   └─ 命中前 5s 粒度比对 ai_config_state.ai_config_version（跨进程失效）
             ├─ 未命中 → SQLite: SELECT * FROM ai_config WHERE id=1
             │   └─ api_key 若是 ENC: 前缀 → crypto.decrypt_api_key
             ├─ _load_env_config()（AI_API_KEY/OPENAI_API_KEY/DEEPSEEK_API_KEY 覆盖）
             └─ api_key 仍空 → 回退 text_provider_configs WHERE is_active=1
         → 返回 dict（_display_api_key 脱敏后吐给前端）
```

### 2.3 数据流（写入链路）

```
PUT /ai/config
  ├─ 脱敏占位符 → 回填库内原值（不解密、不降级）
  ├─ 参数钳制：temperature [0,2]、concurrency [1,64]、max_tokens [256,65536]
  ├─ SSRF 校验：base_url 仅 http/https，可选内网拦截
  ├─ _encrypt_fresh_key：新明文 → ENC: 落库；占位符/密文幂等透传
  ├─ asyncio.to_thread 写 SQLite UPSERT
  ├─ bump_ai_config_version()：清本进程缓存 + 版本号+1（跨进程 ≤5s 收敛）
  ├─ asyncio.to_thread(_audit + record_provider_usage)  ← 本轮 F-NEW-4 改造
  └─ 返回 {status: ok}
```

### 2.4 降级链（5 层，`get_provider_priority_order`）

1. 主配置（ai_config 表 id=1）
2. text_provider_configs 中 is_active=1 的备选厂商（带真实 key）
3. AI Profile 默认配置
4. provider_history 最近使用记录（无 key）
5. 内置兜底（agnes / DeepSeek / SiliconFlow / 通义 / 智谱 / OpenAI）

### 2.5 安全现状（已闭环项）

- API Key 落库统一 `ENC:` 前缀加密（F-1，2026-10-04）；读写路径幂等。
- 所有 HTTP 读接口统一 `_display_api_key` 返回 `***已配置***`，不再回传明文。
- 审计日志 `ai_config_audit` 只记 `mask_key_for_audit` 尾 4 位摘要。
- SSRF：base_url 仅 http/https，`AI_ALLOW_INTERNAL_URL=false` 时拦截内网/元数据地址。
- 跨进程缓存失效：`ai_config_state.ai_config_version` + 5s 防抖。
- 密钥托管：`BID_ASSISTANT_KEY_FILE` 多实例共享、Fernet 轮换脚本 dry-run 可用。

## 4. 本轮修复项清单

### F-NEW-1（P1）：同步探活补代理

- **文件**：`backend/app/services/ai/provider_factory.py`
- **函数**：`_quick_health_check`（约 L860）
- **改动**：`httpx.Client(...)` 增加 `**build_httpx_proxy_settings()`。
- **为什么**：同步版被 `create_provider_with_fallback` 使用，后者经 `asyncio.to_thread` 被 Celery 任务调用。配置 `HTTPS_PROXY` 后，异步链（SSE/路由）走代理而 Celery 链直连失败，降级行为漂移。
- **向后兼容**：未配置代理时 `build_httpx_proxy_settings()` 返回 `{}`，`**{}` 展开为空，行为与改动前完全一致。
- **新增测试**：`TestFNew1SyncHealthCheckProxy`（2 例：有代理传 proxy kwarg、无代理不传）。

### F-NEW-4（P2）：审计/用量记录写库挪出事件循环

- **文件**：`backend/app/routers/ai_config.py`
- **函数**（6 处）：
  1. `save_ai_config`（PUT /ai/config）
  2. `quick_setup`（POST /ai/quick-setup）
  3. `save_text_provider_config`（PUT /ai/provider-configs/{name}）
  4. `activate_text_provider_config`（PUT /ai/provider-configs/{name}/activate）
  5. `save_image_provider_config`（PUT /ai/image-provider-configs/{name}）
  6. `activate_image_provider_config`（PUT /ai/image-provider-configs/{name}/activate）
- **改动**：把原来紧跟 `bump_ai_config_version()` 之后的 `_audit(...)` 与 `record_provider_usage(...)` 同步 SQLite 写，包进 `asyncio.to_thread(...)`。
- **为什么**：这两个函数内部已是 best-effort try/except，但仍占着事件循环做磁盘 I/O；项目其他写路径（主配置 UPSERT）已统一 to_thread，这两处漏了。
- **向后兼容**：调用顺序、参数、异常语义不变；只是执行线程换了。`_audit` 本身已包 try/except，失败不阻断主流程。

## 6. 遗留问题与后续建议

1. **TD-3（两套降级链收敛）**：建议下一轮把 `create_provider_with_fallback`（同步）与 `get_working_provider`（异步）的探活逻辑收敛为一份共享实现（例如抽 `_probe_one(entry) -> (healthy, reason)`，同步版直接调、异步版用 `asyncio.to_thread` 或 httpx.AsyncClient 各写一份薄壳）。需要同步调整 `test_fallback_entry_key_selection_prefers_own` 的源码级断言。
2. **TD-5（保存即激活）**：建议产品确认 `PUT /ai/provider-configs/{name}` 是否应拆为"保存参数"与"激活为主用"两个动作，避免误切主配置。
3. **TD-7（审计 diff）**：在 `ai_config_audit.detail` 中追加 `before=... after=...`，便于追溯。
4. **全量回归**：本轮只跑了文本配置相关 7 个测试文件（96 passed）。建议在空闲时段跑一次全量（约 7 分钟，参考 `_textcfg_full_final_20261004.txt`）确认无跨模块回归。
5. **多环境/多模型**：当前 `ai_config` 是单行 id=1 的全局配置，无"按任务类型/项目选择不同 Profile"的路由层；`ai_profiles` 表已具备结构，后续可在 `get_working_provider` 入口加 `task_type` 维度选择。
