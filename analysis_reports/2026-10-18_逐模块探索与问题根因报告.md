# 二、逐模块深度探索与问题根因分析

> 各模块采用统一模板：功能现状/缺口、工作流程/断点、AI 调用与提示词、数据链与存储、容错/缓存/并发/日志、日志专项证据、问题清单（编号·文件:行·根因·影响·P级·日志证据）。
> 探索方法：5 个 `code-explorer` 子代理并行代码+日志交叉核对；所有结论均附代码行或日志证据。

---

## 模块A：上传解析与要点提取（解析提取、提取项目）

**功能现状**：文本/Office/PDF 解析、图片 OCR、编码降级、原子落盘、异步派发、重提取/清空、要点提取（摘要/评分点/全局事实/清单/工界/工法）均已实现。
**断点（真实数据正确性风险）**：
- A1/P1：解析失败产生空正文，但 `latest_extracted_text` 不校验 `status=failed`，空串直接进 `ANALYSIS_CONTEXT_BLOCK`；而 BOQ/工界/工法提示词（`prompts/analysis.py:78-79,107-108`）强制"原文不足也要编造通用项" → **伪造下游内容入库**。
- A2/P1：分析层（facts/ai）仅读文本，不校验上游文件 `status`，空上下文仍照常跑 AI。
**可观测性缺口**：
- A5/P2：解析 ERROR/WARNING 绝大多数 `rid=-`（异步/Worker 线程未传播 contextvar）。
- A6/P2：多处 `except: logger.debug("[silent-except]")` 吞异常。
- A3/P2：OCR 不可用只写通用 `EMPTY_TEXT_MESSAGE`，原因不透明前端。
- A4/P2：`clear_project_texts` 高并发下 `database is locked`（files.py:2038）。

## 模块B：目录生成 + 全局事实

**功能现状**：直出/分步双路径、L1→L2→L3、标题质量收口、AI 自检、审核回灌、终态 `renumber_outline_ids`、编号位置式 id=编号幂等重排、全局事实三层存储（`analysis` 表）均已实现。
**真实风险**：
- B1/P1：全局事实占位过滤口径不统一——`facts_service.py:12-13` 自陈 `tasks/__init__.py`、`consistency_repair.py` 仍用裸 `json.loads` 不过滤【待填写】占位，可能注入修复正文。
- B2/P1：`global_facts_json` 解析失败降级 147 条**全部 `rid=-`**，生产遇坏值静默丢事实且无请求上下文可追溯。
- B3/P2：`confirmed_summary/confirmed_scoring=0` 软闸门 96 次（带真实 rid），基于未确认摘要/评分生成目录与正文（设计非阻断但有漂移风险）。
- B6/P2：模板化 `number` 与位置式 `id` 双轨，仅 `OUTLINE_NUMBERING_ENABLED` 时算 `number`。
- B7/P2：L3 泛化标题（如"施工准备工作"）多轮修复后残留。
- B11/P2：测试/生产日志未隔离，147 条 facts 警告多为 `'not json'` 测试夹具。

## 模块C：正文生成 + 图表生成

**功能现状**：章节级 AI 生成、顺序/批/并行三种模式（唯一事实源 `config.CONTENT_GENERATION_MODE` 默认 batch）、断点续生、状态机、任务组锁、字数偏差控制、JSON 自修复、图表围栏单一权威化均已实现。
**结论校正（重要）**：任务清单提到的"模板渲染失败 60 次"**日志中不存在**（"模板渲染"×0），真实对应物为 **export 图表渲染失败（error=None）+ mermaid 无后端**。
**真实问题**：
- C3/P1：`render_mermaid_to_bytes` 双路失败返回 None 且无诊断，export 无再降级、直接丢图且 `error=None` 掩盖根因（export.py:1702/1718）。
- C4/P1：配图降级链对已注册 provider 报 `Unknown provider`（运行时 registry 空）；`API Error` 为 key 错（与文本侧 agnes 401 同源，属配置/初始化）。
- C5/P1：Mermaid HTTP 无可用后端，418 条 WARNING 噪声（已降级 PILv2，但消费层不完整）。
- C6/P1：异步边界不校验可等待性：`'MagicMock'/'bytes'/'list' can't be awaited` 共 ~765（测试污染+代码健壮性）。
- C7/P2：章节失败同一错误三处重复记录（内层/包装/SSE）。
- C8~C12/P2：状态机"假完成"窗口、图表占位符压缩被删/复制、concurrency 默认三处不一致（3/4/8）、失败结果缓存 None、测试桩 base_url。
**配置缺口（P0 级影响但属部署）**：C1 AGNES_API_KEY 未配置致文/图 AI 全链路 401；C2 registry broken 实为 monkeypatch 测试噪声（证明 fail-fast 设计正确）。

## 模块D：审核预检 + 导出文档

**功能现状**：一致性规则引擎审计（不调 LLM）、确定性/AI/Agent 三种修复、事实回流、废标覆盖率、DOCX/HTML/PDF 导出、L2 导出缓存、L1 图表缓存、组锁互斥均已实现。
**真实失败（非噪声）**：
- D1/P1：真实一致性审计 `status=failed`（project=8、987031 共 4 次），但 `logger.error("完整审计失败")` 全日志 **0 次**，根因不可追溯。
- D2/P1：SSE 导出 `completed` 事件携带 `check_result`，若含不可序列化对象，`json.dumps` 异常被宽泛 except 捕获，整条流以 `error` 事件终止（文件已生成却误报失败）。
- D3/P1：相邻模块 DB 争用映射为本模块次级失败——`记录导出信息失败: db write failed`（export.py:3194）、`回滚项目步骤失败: db busy`（export.py:219）→ 导出历史丢失、进度卡 6。
**功能缺口**：
- D5/P2：无导出取消 API；无持久化 processing 态，>30min 构建仅靠 TTL reclaim。
- D4/P2：SSE journal 上限 50，并发≥50 时淘汰活动流→resume 404→撞 409。
- D9/P3：图表渲染失败静默跳过+占位符，`error=None` 难调试。
- D11/P3：`check_report_excel` 与导出无关，仅服务查重/废标报表。

## 模块E：提示词 + 文本模型配置

**功能现状**：提示词注册表/缓存（DB优先+硬编码回退+60s冷却）/版本管理/回滚/分层8层消息栈/监控指标、模型配置目录/工厂/路由/降级/限流 rate_gate、Fernet 加密落库+响应掩码、变更历史均已实现。
**关键核查结论（修正误报）**：
- E1（子代理初判"未初始化"）：`image_providers/__init__.py:42` 在包导入时自动 `initialize_registry()`，而 `image_engine.py:1275` 导入 `.image_providers.registry` 会先加载该 `__init__` → **注册表实际已初始化**，E1 误报，不修。配图 `Unknown provider / API Error` 实为**配置/运行时 provider 缺失**，非初始化 bug。
- E7（registry broken 19 条）：实为 `tests/test_leftover_hardening_2026_10_08b.py:385` 用 `monkeypatch` 验证 fail-fast，证明设计正确（拒绝静默降级到矛盾口径）。
- E2/P1：`AGNES_API_KEY` 未配置（config.py:390）→ 文本 provider 401，默认模型不可用（部署缺口）。
- E4/P1：prompt cache DB 加载失败 44 次（"db down"），已正确 60s 冷却回退硬编码（行为一致，但冷却期内用可能过期提示词）。
- E10/P3：`ai_config_service` 全 INFO（912 次"AI 配置已加载"），噪音偏高建议降 DEBUG。
- E11/P2：共享规则 `SHARED_HEADING_RULES/FORBIDDEN_WORDS/OUTPUT_SPEC` adoption_rate=0，复用能力形同虚设。
- E12/P3：无 A-B 测试/灰度、无漂移自动修复（仅告警需人工）。
- E5/E6/P2：提示词变量缺失 ~165 次、残留占位符/坏 `shared` 引用 159 次 → 坏块进模型。
- E3/P2：`NO_SUCH_KEY_FOR_TEST` ~88 次（测试噪声，但 not_found 被计入指标）。
- E9/P2：限流闸门 125 次（免费套餐触顶，AIMD 自适应）。
