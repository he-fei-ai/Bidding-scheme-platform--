## 二、架构图编排专项增强（新增）

在原有“架构图”支持基础上，新增**专属编排提示词**与**类型判定逻辑**，确保架构图生成具备明确的“先判后生”闭环。

### 2.1 架构图子类型分类（编排阶段必须判定）

编排阶段需区分项目具体适用哪种架构图子类型，以适配不同的生成模板：

| 子类型标识       | 适用场景                                                     | 输出格式      | 典型节点示例                                                 |
| :--------------- | :----------------------------------------------------------- | :------------ | :----------------------------------------------------------- |
| `organization`   | **组织管理架构**：项目部岗位设置、管理层级、职责分工、分包管理体系 | ArchNode JSON | 项目经理 → 技术负责人/生产经理/商务经理 → 各专业工长 → 作业班组 |
| `wbs`            | **WBS 分解架构**：单位工程 → 分部工程 → 分项工程 → 检验批（施工范围分解） | ArchNode JSON | 地基与基础 → 土方开挖/桩基工程/地下防水 → 检验批             |
| `system`         | **系统架构**：信息化系统、智能化系统、BIM协同平台、智慧工地架构 | ArchNode JSON | 感知层 → 网络层 → 平台层 → 应用层 → 用户层                   |
| `infrastructure` | **基础设施架构**：机电管线综合、设备系统构成、能源管理系统   | ArchNode JSON | 供电系统/给排水系统/暖通系统 → 子系统 → 设备终端             |

### 2.2 架构图编排提示词（System Prompt 片段）

```markdown
### 编排阶段——架构图判定规则（专项）

你是技术方案编排专家。请根据当前章节的标题与描述，判定是否需要生成架构图。

【触发条件（命中任一项即进入候选）】
1. 章节标题包含：组织机构、项目管理架构、管理体系、岗位配置、职责分工、责任划分、WBS、工作分解、系统架构、网络拓扑、系统模块、子系统、设备构成
2. 章节描述涉及：管理层级（≥2层）、部门/岗位设置、职能划分、汇报关系、数据流向、模块依赖
3. 评分要求明确要求：项目管理架构图、组织架构图、WBS分解图、系统拓扑图

【子类型判定规则】
- 若内容涉及“岗位/部门/人员/职责” → 判定为 organization
- 若内容涉及“工程分解/清单/子分部/工序拆解” → 判定为 wbs
- 若内容涉及“平台/系统/数据流/网络/软件” → 判定为 system
- 若内容涉及“设备/管线/模块/硬件/能源” → 判定为 infrastructure

【输出格式】
{
  "needed": true,
  "type": "architecture",
  "subtype": "organization",    // organization | wbs | system | infrastructure
  "priority": 4,               // 固定权重 4
  "depthHint": 3,              // 预估层级深度（2~5层）
  "nodeCountHint": 8,          // 预估节点数
  "reason": "章节涉及项目管理岗位设置与职责分工，适合用组织架构图表达"
}
```

### 2.3 架构图生成阶段约束强化

在 v3.0 通用约束基础上，新增以下专项约束：

| 子类型           | 节点标签格式要求             | 节点数量区间 | 特殊要求                                            |
| :--------------- | :--------------------------- | :----------- | :-------------------------------------------------- |
| `organization`   | 岗位名称（≤12字） + 可选人数 | 6～18 个     | 最高层节点 ≤2个，副职与正职同层                     |
| `wbs`            | 工程名称（≤20字）            | 5～15 个     | 严格按“单位→分部→分项→检验批”四级限制，禁止跨级合并 |
| `system`         | 模块/层级名称（≤10字）       | 6～12 个     | 必须体现“端-边-云”或“感知-网络-平台-应用”清晰分层   |
| `infrastructure` | 系统/设备名称（≤15字）       | 5～12 个     | 必须体现“系统→子系统→设备→终端”的树状构成           |

## 四、工程场景触发条件补充——特殊句式触发库（新增）

除关键词触发外，增加**句式语义触发**，提升对自然语言描述的捕捉能力：

| 句式模式（正则/语义）                                 | 触发图表类型 | 示例                                                         |
| :---------------------------------------------------- | :----------- | :----------------------------------------------------------- |
| `“先...再...最后...”` / `“分...个阶段”`               | 甘特图       | “本项目分三个阶段推进，先期进行桩基施工，中期完成主体结构，最后进入装饰装修阶段。” |
| `“由...负责...，...向...汇报”`                        | 架构图       | “项目设项目经理1人，下设技术组、生产组、商务组，分别向项目经理汇报。” |

| `“一方面...另一方面...”` / `“与...相比，...高出...”`  | 对比图       | “与常规方案相比，优化后方案成本降低8%，工期缩短15%。”        |

## 五、编排与生成阶段输出约束补充（v3.1）

### 5.1 编排阶段输出格式（更新）

在原有统一格式基础上，新增 `subtype` 字段（适用于架构图），并加入 `matchedKeywords` 字段供日志追踪：

```json
{
  "needed": true,
  "type": "architecture",
  "subtype": "organization",     // 仅架构图有此字段
  "priority": 4,
  "reason": "...",
  "nodeCountHint": 8,
  "depthHint": 3,
  "matchedKeywords": ["组织机构", "岗位配置", "职责分工"],  // 新增，用于审计
  "phaseCountHint": 0,
  "flowHint": "",
  "estimatedPeak": 0
}
```

### 5.2 生成阶段数据校验规则（更新）

| 图表类型 | 新增校验项                                                   |
| :------- | :----------------------------------------------------------- |
| 甘特图   | 任务 ID 不得重复；总工期 ≤ 项目总工期（从事实变量 `planned_duration_days` 读取）；依赖关系不得成环 |
| 流程图   | 节点 ID 仅含 ASCII；无孤立节点（所有节点均存在至少一条入边或出边，首尾节点除外） |
| 架构图   | 根节点有且仅有 1 个；同级节点标签不得完全重复；深度不得超过 5 层 |
| 劳动力图 | 所有阶段下至少有一个工种的数值 > 0；各工种人数之和不为负数   |
| 布局图   | 每个 `subgraph` 必须包含至少 2 个节点；无重叠分区描述        |
| 对比图   | 饼图所有数据项百分比之和 ∈ [99, 101]（允许舍入误差）         |


## 六、全局互斥优先级（v3.1 微调）

|  优先级   | 图表类型   | 说明                                                         |
| :-------: | :--------- | :----------------------------------------------------------- |
| 5（最高） | 甘特图     | 进度计划为独立评分大项，权重最高                             |
|   **4**   | **架构图** | **组织管理与系统架构为核心得分点，与流程图同级（原为同层并列）** |
|     4     | 流程图     | 施工部署与工艺逻辑为必得分项                                 |
|     3     | 劳动力图   | 资源配置类，重要性次之                                       |
|     3     | 布局图     | 总平面布置在市政/房建中占比较高，提升至与劳动力同级          |
|     2     | 对比图     | 辅助性图表，可被其他类型替代                                 |

> **互斥执行逻辑**：当同一章节的编排结果中，`甘特图` 与 `流程图` 同时存在且 `priority` 同为高值时，系统优先保留甘特图，流程图降级为文字描述；`架构图` 与 `流程图` 共存时，根据 `subtype` 进一步判断——若为 `organization` 则保留架构图，若为 `wbs` 则保留流程图。


## 七、与现有提示词体系的衔接说明

v3.1 作为系统级入口规范，与各子图表的编排/生成/修复提示词关系如下：

```text
【本规范 v3.1 — 系统级入口 + 工程语料库】
    │
    ├── 工程分类与标准词库 → 注入所有编排提示词（各图表共享）
    │
    ├── 架构图编排提示词（新增专用规范）
    │   ├── 判定子类型（organization/wbs/system/infrastructure）
```
