## 一、摘要（一页速览）

图表生成是本平台**仅次于正文生成的第二大 AI 能力**，横跨两条技术路线、7 类图表、11 家图像厂商适配，后端核心代码 **15,757 行**，前端 1,640 行，另有 4,372 行设计文档。

**总体判断：能力完整度高，工程质量中等偏下，「设计意图」与「落地实现」存在系统性脱节。**

| 维度 | 评价 | 说明 |
|---|---|---|
| 功能覆盖 | ★★★★☆ | 7 类图表全部可用，双渲染路径，覆盖生成→存储→前端→导出全链路 |
| 架构设计 | ★★★☆☆ | 分层清晰（编排/生成/校验/渲染），但命名误导、双份实现、死代码多 |
| 质量保障 | **★★☆☆☆** | **1,005 行校验器零生产调用**；核心路径测试缺口明显 |
| 安全 | **★★☆☆☆** | 鉴权默认关闭、无内容审核、无体积/魔数校验、前端 innerHTML 注入 |
| 文档一致性 | **★★☆☆☆** | 15 篇文档中至少 6 处与代码冲突，多条款承诺未落地 |

**三条最关键的发现（按严重度排序）：**

1. **`chart_validators.py`（1,005 行 v3.1 规范校验器）在生产链路中零调用**，仅被 `ai/__init__.py` 转出。文档承诺的节点数、层级深度、ID 字符集、饼图百分比和、工期依赖等全部约束**实际不拦截任何数据**。
2. **`AUTH_ENABLED` 默认 `false`（`config.py:167`）**，`POST /api/v1/images/generate` 任何人可匿名调用消耗付费配额。
3. **`easybidding-service/` 是孤立死代码**：未被 backend/frontend 任何一处引用，其 `chartValidators.ts` 是 Python 校验器的「带 bug 旧版」（未修 BUG-FIX-31 跨层标签误报），且 `ChartService._renderMermaid` 返回 mock 数据并写入缓存。

## 四、完整生命周期

```
① 正文生成 (sse_content.py:617)
   AI 在正文写入 <<CHART:类型>> 标记
        ↓
② 标记解析 (sse_charts.py:54 _auto_generate_charts_for_section)
   extract_section_charts (workflows_sections.py:255)
   区分：真实 JSON 数据 / 纯文本提示 hint
   真实数据 → _save_section_field 直接落库
   文本提示 → 转 chart_hints
        ↓
③ 批量编排 (image_engine.py:1328 generate_all_chart_arrangements)
   单次 AI 调用判定 7 类 needed（已由「6 次独立调用」演进为「1 次批量」）
        ↓
④ 并行生成 (sse_charts.py:270 _generate_and_save)
   asyncio.gather 并行调 image_engine 各生成函数
   Mermaid 类：provider.chat 出源码 → validate_mermaid
               失败 → MERMAID_REPAIR_PROMPT 修复 1 次 → 再校验
   JSON 类：provider.chat 出结构化数据
        ↓ 结果落库 sections.{type}_json
⑤ 前端预览 (DiagramPreview.tsx)
   mermaid.render → innerHTML；失败 → 原生 SVG 降级 (renderNativeChartFallback)
        ↓
⑥ 导出 Word (export.py:1481 _add_inline_chart → 1530 _render_commercial)
   ⚠️ 导出时重新渲染，不复用前端 SVG
   L1 内存缓存 → L2 磁盘 ChartCache → L1.5 HTTP(Docker/Railway/mmdc) → L2 PIL 自绘
   全失败 → 插入灰色斜体「【图表渲染失败】」文字，不伪造数据（V6.1 设计，正确）
```

**渲染降级链**（`mermaid_renderer.py:40`）：
- **L1.5 HTTP**：Docker（`MERMAID_SERVICE_URL`，默认 `localhost:8080/render`）→ Railway → mmdc CLI。仅接受合法 Mermaid 语法（`{` 开头跳过）。HTTP 总预算 20s，最多重试 2 次。
- **L2 PIL 自绘**：7 个 v2 渲染器，全部带 `@_render_hq`（300 DPI + 2.5x 超采样）。
- **缓存**：`ChartCache`（renderer:477），MD5 key `f"{type}:{code}"`，LRU 500MB，`.tmp`+`os.replace` 原子写，7 天清理。

**关于 `mermaid_layout.py` 的澄清**：它不是通用布局算法，而是「施工现场总平面布置图」专用渲染器。布局为**固定网格法**（`cols=ceil(sqrt(n*1.5))`，`rows=ceil(n/cols)`，`:126`），区域尺寸硬编码（`zone_w=220*scale`），**防重叠仅靠固定间距、无碰撞检测**，连接线取中心点直线可能穿越其他区域。

## 五、提示词体系

采用 **编排 → 生成 → 修复** 三段式：

- **编排（`*_ARRANGE_SYSTEM`）**：AI 只判 `needed / type / priority / nodeCountHint / depthHint`，**不出代码**。设计上要求「小项目克制配图」。
- **生成（`*_GENERATE_SYSTEM`）**：出 Mermaid 源码或结构化 JSON。
- **修复**：`MERMAID_REPAIR_PROMPT`（`prompts/mermaid.py:12`）用于校验失败后的单次修复。

`CHART_REGISTRY`（`prompts/charts.py:2685`）为 7 类图表的单一注册表，末尾带一致性断言（`:2762`）—— 新增图表类型漏登记会直接启动失败，设计良好。

**AI 自主触发实际有三种并存机制**（与文档描述不一致）：
1. 统一编排 `_ORCH_SYSTEM`（只判 mermaid / image / none）
2. `generate_all_chart_arrangements()` 单次批量判 7 类型 ← **主链路**
3. 正文 `<<CHART:类型>>` 标记强制 `needed=true`（`_apply_chart_hints`）← **实际最可靠**

## 八、风险与缺陷清单

### P0（建议立即处理）

| 问题 | 位置 | 说明 |
|---|---|---|
| 鉴权默认关闭 | `config.py:167` | `AUTH_ENABLED` 默认 `false`，`images.py:24 verify_auth` 匿名放行 → 任何人可调 `POST /images/generate` 消耗付费配额 |

### P1（迭代内处理）

- **两套降级链不一致**：`service.py:28 IMAGE_FALLBACK_PROVIDERS`（7 家）vs `image_engine.py:951 _FALLBACK_CHAIN`（3 家），行为不可预测。
- **两份同名 `ImageGenerationService`**：`image_providers/service.py:133`（活跃）与 `image_engine.py:1547`（V7.0 死代码），极易误用。
- **异常静默**：`mermaid_renderer.py` 13 处 `except Exception`（含 `[silent-except]`），`mermaid_common.py:204` `_render_hq` 兜底 `except: pass`。
- **图片下载无体积/格式校验**：`_download_image` 仅校验非空，`download_and_embed_image:1756` 仅校验 >100 字节；无 MIME/魔数校验，扩展名可被 URL 伪造。SSRF 校验已有（`utils/ssrf.py`），但残留 DNS 重绑定 TOCTOU。
- **无内容审核**：全库无敏感图/NSFW 检测。
- **缓存污染**：`ChartService._renderMermaid`（easybidding）返回 mock 数据并写入缓存；`ChartCache` 无 TTL 自动失效。
- **多图只回传第一张**：`sse_charts.py:644` `return generated_charts[0]`，其余生成结果不回传前端。
- **死代码与无副作用表达式**：`flowchart.py:406`、`gantt.py:213`、`architecture.py:218` 存在求值未赋值的无效语句。
- **配置默认值不一致**：`_get_adapter` 传 `default_size="2K"`，而 dashscope/volcano/baidu 默认 `1024x1024`。
- **`zhipu.py:76`** 端点疑似误拼为 `dashscope/images/generations`；**`volcano.py:87`** 仅传 `ak` 未用 `sk`；**`baidu.py`** `test_connection` 把 401 当成功。

### P2（技术债）

- **命名误导**：`mermaid_service.py` 实为 HTTP 客户端；`render_mermaid()`（`renderer:776`）是空壳直接返回源码。
- **硬编码文案**：默认标题「施工进度计划」「施工现场总平面布置图」「流程图」写死；`_repair_layout_data:380-431` 硬编码 5 个默认区域。
- **魔法数字密集**：`scale=2.5`、`node_w=180/node_h=56`、`tasks[:30]` 截断、`_MAX_ARCH_NODES=120` 等。
- **补丁债务**：代码含 BUG-FIX-30~51、BUG-H-01~03、BUG-E-02~07 等大量补丁注释（如「预渲染缓存 key 含 fig_no 致命中率恒为 0」「_access_order 重启归零致 LRU 失效」），反映链路多次返工。
- **`data/images/1`、`/2` 目录为空**，`data/` 下另有 `app.db`、`tzb.db` 疑似残留库。
