### 2.1 提示词模块（Prompt Engine）

**模块职责**：管理所有 AI 提示词模板，提供统一的"获取-校验-渲染" API。

**核心文件**：

| 文件 | 行数 | 职责 |
|------|------|------|
| `services/ai/prompts/__init__.py` | ~100 | 包入口，触发子模块注册 |
| `services/ai/prompts/_registry.py` | ~300 | 注册表 + 变量提取/校验/渲染 |
| `services/ai/prompts/_cache.py` | ~200 | 线程安全缓存 + DB 优先回退 |
| `services/ai/prompts/outline.py` | ~350 | 目录生成 prompt（8 个） |
| `services/ai/prompts/content.py` | ~200 | 正文生成 prompt（5 个） |
| `services/ai/prompts/charts.py` | ~400 | 图表 prompt（11 个） |
| `services/ai/prompts/mermaid.py` | ~300 | Mermaid 图表 prompt（6 个） |
| `services/ai/prompts/analysis.py` | ~400 | 文件解析 prompt（14 个） |
| `services/ai/prompts/checks.py` | ~200 | 废标/错别字/逻辑（5 个） |
| `services/ai/prompts/_shared.py` | ~50 | 共享规则（禁用词/输出格式） |

**工作流程**：

```
前端 PromptEditorPage 编辑
    │
    ↓ GET /api/v1/prompts/all  (routers/prompts.py)
    │
    ↓ prompts._cache.get_prompt(key, **kwargs)
    │
    ├─ 锁内检查 _prompt_cache（线程安全）
    ├─ None → 从 DB prompt_templates 表加载
    ├─ DB 命中 → 返回 DB 内容
    ├─ DB 未命中 → _ALL_PROMPTS 硬编码回退
    ├─ validate_prompt_variables() 校验变量（大小写不敏感）
    └─ render_prompt() 替换 {VAR} 和 __VAR__ 占位符
         └─ re.sub IGNORECASE + lambda（防反向引用解释）
```

**已修复的历史 BUG（代码中可见）**：
- BUG-FIX-28: DB 编辑后变量缺失跳过校验 → 统一校验
- BUG-FIX-44: re.sub 反向引用解释 + kwargs 含 None → lambda + None 过滤
- BUG-FIX-45: _prompt_cache 空字典导致永不重试 DB → 保持 None 触发重试
- BUG-FIX-B1: 变量大小写不敏感匹配

**设计亮点**：
- 注册表模式（所有 prompt 自动累积到 `_ALL_PROMPTS`）
- DB 优先 + 硬编码回退（新部署无 DB 也能跑）
- 变量渲染支持 `{VAR}` 和 `__VAR__` 两种占位符

### 2.2 目录生成模块

**模块职责**：根据招标文件自动生成技术标目录树（L1→L2→L3 三级结构）。

**核心文件**：

| 文件 | 行数 | 职责 |
|------|------|------|
| `routers/sse/sse_outline.py` | ~1400 | SSE 流式端点 + 断点续生 |
| `services/ai/workflows_outline_v51.py` | ~2400 | V5.1 AI 工作流（唯一生产路径） |
| `services/v51_state.py` | ~200 | V5.1 状态持久化（断点续生） |

**工作流程（V5.1 唯一路径）**：

```
前端 OutlineEditorPage
    │ EventSource GET /api/v1/sse/outline/{project_id}
    ↓
sse_outline.generate_outline_sse_impl()
    │
    ├─ ① task_registry.create_task(task_type="outline_v51")
    ├─ ② 重连检测：复用后台任务 or 拒绝静默重跑 (BUG-FIX-42)
    ├─ ③ _extract_project_context_with_retry()
    │     → summary / scoring_points / industry_profile
    │
    ├─ ④ workflows_outline_v51.generate_outline_v51()  ← AI 核心
    │     ├─ _generate_level1_v51()   L1 一级目录（评分项映射）
    │     ├─ _generate_level2_v51()   L2 二级目录（并发 DynamicSemaphore）
    │     ├─ _generate_level3_v51()   L3 三级目录（并发）
    │     ├─ _self_check_v51()        AI 自检（问题+修复建议）
    │     └─ _auto_fix_issues()        自动修复
    │
    ├─ ⑤ _save_and_finalize_outline()  DELETE + INSERT（事务）
    │
    ├─ ⑥ V5.1 状态持久化（断点续生）
    │     ├─ save_v51_state_to_db() ← finally 块
    │     └─ clear_v51_state_from_db() ← 成功后清理
    │
    └─ ⑦ 兜底：主 Provider 失败 → 切换 fallback provider 重试
```

**并发控制**：

```python
# workflows_outline_v51.py 内部
semaphore = DynamicSemaphore(max_concurrency=4)
async with semaphore:
    result = await _generate_level3_v51(...)
```

**进度阶段映射（8 阶段）**：
1. 上下文提取 → 20%
2. L1 生成 → 35%
3. L2 生成 → 55%
4. L3 生成 → 75%
5. AI 自检 → 85%
6. 自动修复 → 95%
7. 保存 → 100%

**设计亮点**：
- 任务与 SSE 解耦：任务在 task_registry 独立运行，断线不影响后台
- 8 阶段进度映射（BUG-FIX-26: step 从 0-based 改为 1-based）
- 并发控制：任务级 DynamicSemaphore，避免全局竞争
- 容错：单节点失败默认填充，不中止整体

### 2.4 图表生成与渲染模块

**模块职责**：生成技术标中的 Mermaid 图表（甘特图/流程图/架构图/劳动力图/对比图/布局图/时间线），并在 DOCX 导出时渲染为图片。

**生成侧（正文生成时）**：

```
section_complete_callback → chart_queue.put(result)
    │
    ↓ chart_worker pool (2-4 workers)
    │
    ↓ extract_section_charts(provider, section_data, ...)
    │
    ├─ AI 编排判断: 这个章节需要什么图?
    │
    └─ 分别调用各 Mermaid generator:
         mermaid_gantt.generate_mermaid_gantt()       → gantt_json
         mermaid_flowchart.generate_mermaid_flowchart() → flowchart_json
         mermaid_architecture.generate_mermaid_architecture() → architecture_json
         mermaid_labor.generate_mermaid_labor()        → labor_json
         mermaid_comparison.generate_mermaid_comparison() → comparison_json
         mermaid_layout.generate_mermaid_layout()      → layout_json
         mermaid_timeline.generate_mermaid_timeline()   → timeline_json
    │
    └─ 保存到 sections 表对应 *_json 字段
```

**渲染侧（DOCX 导出时）**：

```
build_docx(project_id, config)
    │
    ↓ 遍历章节树 → _render_section_charts(doc, section, title, config)
    │
    ↓ 遍历 _CHART_TYPE_MAP (7 种图表)
    │
    ├─ 有 DB *_json 数据 → _add_inline_chart()
    │     ├─ render_mermaid_to_bytes(mermaid_code, dpi=300)
    │     │   ├─ HTTP POST → MERMAID_SERVICE_URL（Docker mermaid-service）
    │     │   ├─ 失败 → 本地 headless 渲染（Puppeteer/Selenium）
    │     │   └─ ChartCache 哈希缓存（避免重复渲染）
    │     └─ 插入 docx.InlineImage
    │
    └─ 无数据 → 跳过（V7.0 无降级原则）
```

**Mermaid 渲染服务**：

| 方式 | 入口 | 说明 |
|------|------|------|
| 远程服务 | `MERMAID_SERVICE_URL` | Docker 容器化 mermaid-service |
| 本地降级 | headless browser | Puppeteer/Selenium |
| 缓存 | ChartCache | Mermaid 代码哈希，命中跳过渲染 |

**设计亮点**：
- 生成-渲染分离：正文生成时 AI 编排，导出时 Mermaid 渲染
- 7 种图表统一接口，章节有什么图就渲染什么
- 无降级原则：没数据就跳过，不生成占位图或 Markdown

### 2.6 前后端同步架构

**前端技术栈**：React 18 + TypeScript + Vite + Ant Design + Zustand-free

| 文件 | 职责 |
|------|------|
| `api/index.ts` | Axios 拦截器 + 断线重连 + 指数退避 + JWT |
| `services/taskStore.ts` | 全局任务状态单例（跨页面追踪，版本号防竞态） |
| `App.tsx` | 路由 + 代码分割（15 个 lazy 页面） |

**后端技术栈**：FastAPI + SQLite + asyncio + SSE + TaskRegistry

| 文件 | 职责 |
|------|------|
| `routers/sse/sse_*.py` | SSE 流式端点（text/event-stream） |
| `services/task_registry.py` | 任务状态管理 + 进度广播 |
| `services/v51_state.py` | V5.1 状态持久化（断点续生） |

**同步机制**：

```
┌──────────────┐   SSE EventSource GET    ┌──────────────┐
│   Frontend    │ ──────────────────────→ │   Backend    │
│               │ ←───── StreamingResponse ────│             │
│               │    (text/event-stream)  │              │
│               │    {status, progress, ...}│             │
└──────────────┘                          └──────────────┘
     │                                           │
     │ 断线 → EventSource.onerror                │
     │ → taskStore 标记 disconnected             │
     │ → 后台任务继续（task_registry 独立运行）    │
     │                                           │
     │ 重连: 新 EventSource + token 查询参数     │
     └───────────────────────────────────────────┘
```

**SSE 关键 Headers**：

```python
# sse_shared.py 中
headers = {
    "Cache-Control": "no-cache, no-transform",
    "X-Accel-Buffering": "no",  # Nginx 防缓冲
    "Content-Type": "text/event-stream; charset=utf-8",
}
```

**设计亮点**：
- SSE 而非 WebSocket：单向流式推送，更简单可靠
- task_registry 任务-SSE 解耦：断线不影响后台
- 版本号防竞态：taskStore 用 `version: int` 防止 setTimeout 过期回调覆盖新状态
- 代码分割：15 个页面用 `React.lazy() + Suspense`

## 三、真实 BUG 清单与修复

### BUG-1：export.py `_render_section_charts` 硬访问 id 属性

**严重等级**：P0（潜在生产崩溃）

**问题描述**：
`_render_section_charts` 方法的日志硬编码 `section_detail.id`，但传入对象可能是 dict、Pydantic 模型或测试 mock 类，非总是有 `.id` 属性。DOCX 导出时若章节对象类型变化会抛出 `AttributeError`。

**代码位置**：

```python
# 修改前 — backend/app/services/export.py:2883
logger.info(
    "[V7.0 图表渲染] section=%s title=%s 渲染 %d 张 DB 绑定图表",
    section_detail.id,                                    # ← 硬访问
    getattr(section_detail, "title", "")[:30],
    rendered_count,
)
```

**修复**：

```python
# 修改后 — backend/app/services/export.py:2883
logger.info(
    "[V7.0 图表渲染] section=%s title=%s 渲染 %d 张 DB 绑定图表",
    getattr(section_detail, "id", "unknown"),             # ← 安全访问
    getattr(section_detail, "title", "")[:30],
    rendered_count,
)
```

**验证**：`test_render_section_charts_no_placeholder_text` 通过。

**关联观察**：同一方法在 L2770 已经用了 `getattr(section_detail, "id", None)`，说明开发者之前已意识到这个问题但遗漏了日志处。修复后两处风格统一。

### BUG-5：自检 prompt 缺少"至少4个节点"关键词

**严重等级**：P2（测试断言过时 + prompt 文案不清晰）

**问题描述**：

## 九、经验沉淀

### 踩坑记录

1. **不要假设对象结构**：`_render_section_charts` 接收的 `section_detail` 可能是 dict、Pydantic 模型或 mock 类，对属性访问一律用 `getattr(obj, "key", default)`。
2. **Prompt API 升级方向**：直接调 `render_prompt()` 已升级为 `get_prompt(key, **kwargs)` 统一入口，内部自动调 render_prompt + validate_prompt_variables + DB 回退，且支持 DB 编辑生效。测试应指向最终 API。
3. **代码拆分后测试路径更新**：原 `sse_handlers.py` 拆分为 `sse/` 子包后，所有断言模块名的测试都需要更新 import 路径。这是架构演进的必然产物，可考虑在 CI 中加一个"测试-代码路径一致性"检查。
4. **Mock 类设计**：测试中创建 mock 类时，尽量让它模拟真实 Pydantic 模型的接口（含 `.id` 属性），而不是让生产代码去适配 mock。

### 可复用结论

| 结论 | 适用场景 |
|------|----------|
| 属性访问一律 `getattr()` | 接收 dict/Pydantic/mock 混合对象的函数 |
| Prompt 统一走 `get_prompt()` | 任何需要调 AI 的模块 |
| 测试用动态 import | 检查模块是否含某函数/常量时，避免硬编码路径 |
| SSE 端点必须设 `X-Accel-Buffering: no` | 防止 Nginx 缓冲导致前端收不到实时推送 |
