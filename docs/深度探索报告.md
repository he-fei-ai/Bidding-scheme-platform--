## 二、核心模块分析

### 2.1 提示词模块 (`services/ai/prompts/`)

**结构**：14 个子模块，涵盖分析/目录/正文/图表/废标/知识库/行业树等

**数据流**：
```
get_prompt(key) → LRU缓存(200条) → DB ai_prompts表 → 硬编码回退
启动时：reload_prompt_cache() 预热所有提示词到内存
```

**关键设计**：
- DB 优先：支持前端编辑持久化
- 变量提取：`_VARIABLE_PATTERN` 自动提取 `{var}` 和 `__VAR__`
- 零宽字符清洗：清理 `\u00AD\u200B\u200C\u200D\uFEFF`

### 2.2 目录生成模块

**四种策略**：

| 策略 | 适用场景 | 核心特点 |
|---|---|---|
| **v51** | 最新生产 | 参考知识库自主取舍，多阶段审核 |
| **v3** | 稳定生产 | 28章固定基石，V6.0智能排序 |
| **v2/one_shot** | 快速生成 | 单次AI调用生成完整三级目录 |
| **step_by_step** | 精细控制 | 分步生成L1→L2→L3 |

**V5.1工作流**：
```
AI生成一级目录 → 校验 → 逐章生成二级 → 校验 → 逐二级生成三级
→ AI自检 → 自动修复 → 人工审核门禁
```

### 2.3 正文生成模块

```
generate_sections(provider, leaves, ...)
  → DynamicSemaphore + AdaptiveConcurrencyController
  → 遍历叶子节点：缓存检查 → 构建提示词 → AI调用 → 质量评估 → 写库 → 推送进度
  → 自适应并发调整
```

**关键特性**：
- 内容编排：先判断内容类型（text/table/flowchart/gantt等）
- 字数控制：`target_words` + `useWordSampling` + `useFallbackExpand`
- 增量生成：支持暂停/恢复，断点续传

### 2.4 图表渲染模块

**7种图表类型** + 1种配图：
- flowchart/gantt/architecture/labor/comparison/layout/timeline → PIL渲染
- illustration → 外部AI图像生成API

**渲染引擎** (`mermaid_renderer.py`):
- 不用mmdc：自研PIL渲染器，避免Node.js依赖
- 300 DPI高保真，`@_render_hq`装饰器
- 自动检测Windows中文字体
- 文件级ChartCache缓存

### 2.5 导出模块 (`export.py`)

**`build_docx()`流程**：
```
查询章节树 → 并行预渲染图表 → 创建Document → 添加标题样式/目录域
→ 遍历章节：标题编号(八级) → 解析内容(文本/表格/图表/图片)
→ 文档校验 → 保存 → 缓存导出结果
```

**缓存机制**：
- 内容指纹：章节内容+图表JSON的哈希
- 图表预渲染：ThreadPoolExecutor并行
- 内联标记缓存：TTL 5分钟，LRU 200条

### 2.6 AI调用层

**Provider工厂** (`provider_factory.py`):
```
优先级链（严格顺序）：
1. 当前保存配置(ai_config表)
2. 最近使用历史(provider_history表)
3. 内置兜底提供商(DeepSeek/SiliconFlow/通义/智谱)
4. 全部失败 → 返回主配置实例
```

**OpenAI兼容Provider** (`providers/openai_compatible.py`):
- 重试机制：普通错误max_retries次 + 空内容+length专属额外3次
- 超时自适应：max_tokens≥16000时timeout扩展到180s
- 429限流：解析retry-after头+指数退避
- 取消支持：cancel_event参数

### 2.7 数据库层 (`db.py`)

**连接池设计**：
- 线程级隔离：`threading.local()`缓存连接
- 最大连接数：32
- 死线程回收：60s空闲且不在`threading.enumerate()`中视为死线程
- 写锁串行化：全局`threading.RLock`，超时60s
- WAL模式：允许并发读，写操作串行
