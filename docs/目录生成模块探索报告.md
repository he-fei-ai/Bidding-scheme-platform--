## 一、模块概述

目录生成模块负责为投标项目自动构建三级目录树（L1→L2→L3），是整个标书智能体（Bid Agent）的入口级功能。当前主力工作流为 **V5.1**，辅以兼容的 V3 分步生成模式。

**核心文件：**
| 层级 | 文件 | 行数 | 职责 |
|------|------|------|------|
| 前端入口 | `frontend/src/pages/OutlineEditorPage.tsx` | ~400行 | SSE 连接、进度展示、树形交互 |
| API 层 | `frontend/src/api/index.ts` | ~30行 | URL构建、EventSource封装 |
| 路由层 | `backend/app/routers/sse_handlers.py` | ~2100行 | SSE端点、事件循环、任务注册 |
| 路由层 | `backend/app/routers/sections.py` | ~300行 | 目录 CRUD API |
| 核心工作流 | `backend/app/services/ai/workflows_outline_v51.py` | ~2778行 | V5.1 三阶段生成主逻辑 |
| 辅助工作流 | `backend/app/services/ai/workflows_outline_v2v3.py` | ~3100行 | V3 分步、兜底补全、去重 |

### 各步骤耗时分布（典型项目）

| 步骤 | 预估耗时 | 说明 |
|------|----------|------|
| L1 生成 | 5-15s | 单次AI调用，max_tokens=8192 |
| L1 审核 | 用户决定 | 可跳过 |
| L2 生成 | 30-120s | N个L1节点并发，受Semaphore限制 |

| L3 生成 | 60-180s | M×N次AI调用，按队列分批 |

| AI 自检 | 10-30s | 单次AI调用 |
| 最终审核 | 用户决定 | 可跳过 |

### 3.2 核心提示词设计要点

#### L1 提示词（[outline.py:601-628](file:///j:/编程/招投标方案平台/backend/app/services/ai/prompts/outline.py#L601-L628)）

```
核心规则：
1. 一一映射：每个评分项 → 一个一级章节
2. 标题优化：在评分项文字基础上专业化调整
3. 覆盖原则：评分要求中的每个技术点都有对应章节
4. 排序：总纲→施工部署→专项方案→管理措施→进度资源→配合协调→收尾
5. 格式：JSON数组，每项含 id/title/description
```

**设计亮点：** 引入 `rating_item → new_title` 映射机制，确保评分点 100% 覆盖。

#### L2 提示词（[outline.py:632-662](file:///j:/编程/招投标方案平台/backend/app/services/ai/prompts/outline.py#L632-L662)）

```
二三级标题规范：
- 二级：章节主题范畴（分类性、综合性）
- 三级：具体执行条目（工程部位、材料名称、工艺工法）
- 差异化铁律：二级≠三级核心词干
  ❌ 二级="质量管理"→三级="质量控制措施"（几乎等同）
  ✅ 二级="质量保证体系"→三级="屋面隐蔽工程验收"（完全不同）
- 绝对禁用词：基本要求、实施要点、主要内容、关键措施...（60+）
```

**设计亮点：** 预构建骨架模式——AI 只需填充 title/description，禁止修改 JSON 结构，大幅降低输出不稳定风险。

#### L3 提示词（[outline.py:666-704](file:///j:/编程/招投标方案平台/backend/app/services/ai/prompts/outline.py#L666-L704)）

```
5种标题结构模式：
- 工艺型：{材料/部件}+{工艺/方法}
- 部位型：{建筑部位}+{施工内容}
- 措施型：{风险/难点}+{应对方法}
- 阶段型：{施工阶段}+{工作内容}
- 标准型：{标准/规范}+{执行要点}

跨章节约束：禁止相同句式结构、禁止仅差后缀词
```

#### 自检提示词（[outline.py:708-718](file:///j:/编程/招投标方案平台/backend/app/services/ai/prompts/outline.py#L708-L718)）

6维度检查：完整性、中英混用、内容重叠、节点数量、跨层级重复、二三级差异化。

## 七、待改进方向

### 7.1 当前已知风险点

1. **AI 输出格式不稳定**：虽然 `_normalize_to_list` 有多层兜底，但当 AI 返回完全非结构化文本时仍可能失败
2. **L3 自检的误报率**：启发式相似度检测（Jaccard + LCS + bigrams）对长标题组合存在误判
3. **并发上限硬编码**：`CONCURRENCY_LIMIT = 16/32` 未根据实际 API 限额动态调整
4. **V3/V51 策略切换**：前端有 `strategy` 参数，但两套代码路径存在维护分裂

### 7.2 建议优化

1. **增加 L1 生成结果的 schema 强校验**（Pydantic）
2. **L3 自检改为 LLM-only 判定**，减少启发式误报
3. **将 V3 和 V5.1 的 `_uniquify_outline_titles` 等公共函数统一到 v51 工作流**
4. **增加生成耗时监控**（目前仅有 logger，无告警）
5. **考虑将 `_ensure_min_children` 的兜底标题质量进一步提升**（当前模板较机械）
