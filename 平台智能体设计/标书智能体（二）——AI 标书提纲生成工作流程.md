# AI 标书提纲生成工作流程

根据文档内容，系统提供了**两套方案**，根据标书长度和 AI 模型能力自动选择：

---

## 方案一：短标书 + 强模型（一次性生成）

> 适用场景：标书 ≤ 3~5 万字，AI 模型支持长输出（如 glm-4.5、doubao-seed-1-6，约 8000 token）

### 工作流程

```
步骤 1：准备输入数据
   ├── 项目概述（overview）
   └── 技术评分要求（requirements）
                 ↓
步骤 2：构建提示词
   ├── SystemPrompt：角色定义 + 输出规范 + JSON 格式要求
   └── UserPrompt：填充 overview + requirements 占位符
                 ↓
步骤 3：调用 AI 模型
   └── 一次性生成完整三级目录 JSON
                 ↓
步骤 4：JSON 解析与校验
   ├── 格式校验（是否为合法 JSON）
   ├── 结构校验（id/title/description/children 字段完整）
   └── 层级校验（三级目录完整）
                 ↓
步骤 5：输出完整目录
   └── 返回标准 JSON 格式的三级目录
```

### 输入数据结构

```json
{
  "outline": [
    {
      "id": "1",
      "title": "",
      "description": "",
      "children": [
        {
          "id": "1.1",
          "title": "",
          "description": "",
          "children": [
            {
              "id": "1.1.1",
              "title": "",
              "description": ""
            }
          ]
        }
      ]
    }
  ]
}
```

### 核心规则

1. 一级目录名称必须与技术评分要求中的章节名称**一致**
2. 如果评分要求中没有章节名称，则根据评分内容**生成**一级目录名称
3. 目录深度统一为**三级**
4. **只返回 JSON**，不允许任何额外说明文字

---

## 方案二：长标书 + 普通模型（分步生成）

> 适用场景：标书 ≥ 几万~几十万字，AI 模型输出受限（约 1500 token），如 glm-4-air
> 设计思想：将大规模生成任务拆解为多个小任务，“分而治之”

### 总体工作流程

```
┌─────────────────────────────────────────────────────────┐
│  步骤 1：生成一级目录                                    │
│  输入：overview + requirements                          │
│  输出：一级目录列表（与评分项一一对应）                   │
└─────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────┐
│  步骤 2：为每个一级目录分配二三级节点数量                │
│  逻辑：随机分布，保证各章节叶子节点数量合理              │
│  输出：nodes_distribution 配置                         │
└─────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────┐
│  步骤 3：并发生成每个一级目录下的二三级目录              │
│  对每个一级目录：                                        │
│    3a. 代码生成 JSON 框架（结构固定，标题留空）         │
│    3b. 传入 other_outline（其他章节标题，避免重复）     │
│    3c. AI 补全标题和描述                                │
│    3d. check_json 校验结构是否与框架一致                │
│    3e. 校验失败 → 重试（最多 3 次）                    │
│    3f. 校验成功 → 保存该章节的完整目录                  │
└─────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────┐
│  步骤 4：合并所有章节                                    │
│  将所有一级目录及其子目录拼接为完整 JSON                 │
└─────────────────────────────────────────────────────────┘
```

---

### 步骤 1：生成一级目录

**输入**：`overview` + `requirements`

**SystemPrompt 核心指令**：
1. 一级目录数量与评分要求**一一对应**
2. 标题需做**简单修改**，不能完全照抄评分项原文
3. 只设计一级标题

**输出格式**：

```json
{
  "rating_item": "原评分项",
  "new_title": "根据评分项修改的标题"
}
```

**UserPrompt**：填充 overview + requirements

---

### 步骤 2：节点数量分配

**目的**：确定每个一级目录下分配多少个二级，每个二级下分配多少个三级（叶子节点）。

**策略**：随机分布，让部分章节更丰富，更符合真实标书结构。

```python
nodes_distribution = {
    'level2_nodes': [4, 5, 3, ...],        # 每个一级下的二级数量
    'leaf_per_level2': [[3,4,2,...], ...]  # 每个二级下的三级数量
}
```

---

### 步骤 3：逐章生成二三级目录（关键环节）

#### 3a. 代码生成 JSON 框架

用程序预先构建好 JSON 骨架，AI **只需要填标题**，**禁止修改结构**：

```python
def generate_one_outline_json_by_level1(level1_title, level1_index, nodes_distribution):
    # 1. 获取该一级下的二级数量和叶子分布
    level2_count = nodes_distribution['level2_nodes'][level1_index - 1]
    leaf_distribution = nodes_distribution['leaf_per_level2'][level1_index - 1]
    
    # 2. 创建一级节点（标题已确定）
    level1_node = {
        "id": f"{level1_index}",
        "title": level1_title,
        "description": "",
        "children": []
    }
    
    # 3. 创建二级节点（标题留空）
    for j in range(level2_count):
        level2_node = {
            "id": f"{level1_index}.{j+1}",
            "title": "",   # ← AI 填充
            "description": "",  # ← AI 填充
            "children": []
        }
        # 4. 创建三级节点（标题留空）
        for k in range(leaf_distribution[j]):
            level2_node["children"].append({
                "id": f"{level1_index}.{j+1}.{k+1}",
                "title": "",   # ← AI 填充
                "description": ""  # ← AI 填充
            })
        level1_node["children"].append(level2_node)
    
    return level1_node
```

#### 3b. 传入其他章节标题（避免重复）

```python
other_outline = "\n".join([f"{j+1}. {node['new_title']}" 
                    for j, node in enumerate(level_l1) 
                    if j != i])  # 排除当前章节
```

AI 在生成当前章节时参考其他章节标题，确保 **内容不重叠**。

#### 3c. AI 补全标题与描述

**SystemPrompt 核心指令**：
1. 在原 JSON 结构上**补全** title 和 description
2. **禁止**修改 JSON 结构
3. **禁止**修改一级标题
4. 二级标题根据一级标题撰写，三级标题根据二级标题撰写
5. 参考 `other_outline` 避免重复

**UserPrompt**：传入 overview + requirements + other_outline + json_outline

#### 3d. check_json 校验（关键质量控制）

校验 AI 返回的 JSON 是否与传入框架**结构一致**：

```python
def check_json(json_str: str, schema: str | dict) -> tuple[bool, str]:
    # 1. 解析目标 JSON
    # 2. 逐层递归对比：
    #    - 类型是否匹配（dict/list/int/str）
    #    - 键是否存在
    #    - 列表元素格式是否与模板一致
    # 3. 返回 (是否通过, 错误信息)
```

#### 3e. 重试机制（最多 3 次）

- 校验失败 → 重新执行该章节的 AI 调用
- 连续 3 次失败 → 报错，由人工介入

---

### 步骤 4：合并所有章节

将所有一级目录拼接为完整 JSON，输出最终提纲。

```json
{
  "outline": [
    { "id": "1", "title": "第一章...", "children": [...] },
    { "id": "2", "title": "第二章...", "children": [...] },
    ...
  ]
}
```

## 两套方案对比

| 对比维度         | 方案一（一次性生成）     | 方案二（分步生成）             |
| ---------------- | ------------------------ | ------------------------------ |
| **适用场景**     | 短标书（≤5 万字）        | 长标书（几万~几十万字）        |
| **AI 模型要求**  | 强模型（如 glm-4.5）     | 普通模型（如 glm-4-air）       |
| **输出长度限制** | ~8000 token              | ~1500 token                    |
| **生成次数**     | 1 次                     | 1 + N 次（N = 一级章节数）     |
| **并发支持**     | 不适用                   | ✅ 多个一级目录可并发生成       |
| **质量控制**     | JSON 格式校验            | check_json 结构比对 + 3 次重试 |
| **防重复机制**   | 无（一次性生成天然避免） | 传入 other_outline 显式约束    |
| **提纲长度**     | 受 AI 输出限制           | 理论无限（分而治之）           |

## 关键机制总结

| 机制                       | 说明                                                     |
| -------------------------- | -------------------------------------------------------- |
| **代码生成框架 + AI 补全** | 结构由程序保证，AI 只填内容，解决“输出不稳定”问题        |
| **check_json 校验**        | 逐层递归比对结构，确保 AI 没破坏框架，解决“格式错误”问题 |
| **重试机制（最多 3 次）**  | 校验失败自动重试，提高成功率                             |
| **other_outline 防重复**   | 每章生成时参考同级章节标题，解决“内容交叉”问题           |
| **并发生成**               | 多一级目录同时生成，提高效率                             |
| **随机节点分布**           | 让各章节叶子数量有差异，更符合真实标书                   |
